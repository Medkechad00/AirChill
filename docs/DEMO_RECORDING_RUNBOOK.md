# AirChill-Style AI Service Intake — Demo Recording Runbook

**Purpose:** A short, professional, client-facing sales demo of the existing prototype, not a claim that it is installed at AirChill or integrated with AirChill's actual WhatsApp account.

**Status:** The project owner reported on 2026-11-13 that the full synthetic-data flow passed locally: AI chat -> Google Sheets saved row -> single Gmail staff notification -> Next.js live dashboard -> status update -> Google Sheets persisted after refresh. These tests have **not** been independently reproduced by the assistant.

## Demo scope and accuracy

- This prototype uses the **n8n test chat**, not live WhatsApp Business API messaging.
- It demonstrates a workflow that **could be adapted** for an authorized WhatsApp integration.
- The dashboard accesses a test Google Sheet through protected n8n webhooks.
- Staff confirms quotes and appointments; the bot does not diagnose AC failures, quote repairs, dispatch technicians, or reserve time slots.
- Use invented customer names, addresses, and problems in the recording.
- Do not show your actual webhook URLs, API keys, dashboard password, n8n credentials, personal email address, or real customer records.
- Mark the video and UI where appropriate: **Illustrative prototype — not affiliated with AirChill**.

## Preparation (before pressing Record)

1. Start the Next.js dashboard and log in privately; confirm it is in Live Mode.
2. Prepare a **new fictional** request in n8n chat, and arrange browser windows for easy switching: chat, dashboard, Gmail test inbox, Google Sheets.
3. Ensure the test Sheet contains only demo records. Use a fictional customer name and generic area, and never expose contact identifiers.
4. In Gmail, hide/blur personal sender and recipient information before recording.
5. Check notification polling, search/filter, and request detail view once privately.
6. Set screen resolution to 1920×1080 (16:9), browser zoom around 100%, silence pop-ups and desktop notifications. Aim for one clean take.
7. Avoid showing developer tools or `.env.local`.

## Sample conversation (fictional)

Customer:
> Hi, I'm Maya. I'm in a villa in Dubai Marina and one of our four AC units isn't cooling. Can someone take a look?

AI:
> I can prepare the request for the service team. Is the issue affecting only one unit? And do you have a preferred visit window?

Customer:
> Yes, only one unit. Tomorrow afternoon would be best.

AI should gather any other required information, present a brief accurate summary, and ask for confirmation.

Customer:
> CONFIRM

Expected state: one new Google Sheet request, status `Pending staff review`; one staff email notification; the same request becomes visible on dashboard refresh.

## 85-second storyboarding plan

| Time | On screen | Short voice-over / caption |
|---|---|---|
| 0–8 s | Title: `From customer message to organized service request` | “Here’s a prototype for handling AC service inquiries without a long back-and-forth.” |
| 8–30 s | n8n test chat, with a fictional customer request | “The assistant understands the customer's issue, asks for missing details and prepares a clear summary.” |
| 30–43 s | Final summary and customer confirmation | “Nothing gets passed along as a completed intake until the customer confirms the details.” |
| 43–55 s | Google Sheets row (hide IDs/contact info) | “The confirmed request is stored in a structured service queue.” |
| 55–65 s | Sanitized test Gmail notification | “A staff notification is sent so a person can review and follow up.” |
| 65–80 s | Dashboard live queue -> details -> `In progress` | “The team can inspect the request, change its status, and see the same update reflected in the system.” |
| 80–85 s | Final title / subtle CTA | “A practical workflow that can be customized to the business's current tools.” |

Show a visual proof of status persistence by briefly refreshing the dashboard after changing it, but do not linger on technical setup screens.
